# 重生之研究牲任务系统

当前版本包含 Phase 1 应用骨架、Phase 2 任务管理、Phase 3 XP/金币成长、Phase 4 总览/任务列表、Phase 5 任务看板、Phase 6 日历视图、Phase 7 Boss/子任务、Phase 8 常驻奖励商店、Phase 9 每日奖励和 Phase 10 成就系统。使用原生 HTML、CSS、JavaScript，无构建步骤、第三方运行依赖或服务端。

## 启动

推荐双击 `start-local.cmd`，在启动窗口中访问 `http://127.0.0.1:4317`。需要安装 Node.js 18 或更高版本；项目不需要安装第三方依赖。保持启动窗口运行，关闭窗口或按 Ctrl+C 会停止服务。

此方式将完整应用数据保存在项目目录的 `data/state.json`。迁移到 D 盘或 E 盘时，先停止服务，再复制整个项目文件夹，并从新位置运行 `start-local.cmd`。`data/` 已加入 `.gitignore`，避免任务内容被意外提交。

仍可直接打开 `index.html` 使用浏览器本地存储模式，但该模式的数据依赖浏览器配置，不会保存在项目目录，也不会自动与项目文件 JSON 同步。项目目录模式是推荐方式。

## 当前功能

8-bit 像素风响应式界面；任务新增、查看、编辑、删除、完成/重新打开；主线/支线、主线分支、Boss 挑战、优先级、稀有度、一次性/日常/周常周期、日期、标签与进展记录；总览显示今日安排、逾期事项和未来 7 天计划；任务列表卡片显示按 100% 完成度估算的 XP/金币奖励，并支持常用和高级筛选及排序；任务看板按待办、进行中、搁置、已完成分列，可直接变更状态，完成时沿用完成度评分和一次性发奖规则；月历按计划日期显示任务，支持月份导航、回到今天、选日、打开任务详情及逐日表情心情标记（保存在本地浏览器）；Boss 详情可创建和查看子任务及汇总进度；角色等级、累计 XP、金币余额及奖励流水。

Boss 与子任务采用保守的独立完成规则：父任务和子任务都需分别更改状态并分别填写完成度；双方奖励只在各自首次完成时发放，不会因父子状态联动而额外发奖。Boss 完成不会自动完成子任务，子任务完成也不会自动完成 Boss。暂不支持嵌套子任务；删除 Boss 时子任务保留并解除关联。

奖励商店初始为空；添加时可从奶茶、游戏时间、电影和外出游玩等名称/描述灵感开始，金币价格始终由用户设置。兑换时会确认名称和花费、校验金币余额，并在经济流水中保存当时的奖励名称和花费。停用或编辑奖励不会改写旧兑换记录；XP 不参与消费。日历心情标记与商店数据均保存在浏览器本地状态中。

每日奖励按用户本地日历日计算；候选任务当天完成度累计达到 500% 后，可领取 1 小时游戏时间。可选模板为科研 1h、找工 1h、学业 1h、运动一次、自学 1h；选择后会创建普通任务并按常规建议值发 XP/金币。仅由当日候选模板创建且在当天完成的任务计入每日进度，使用原始完成度相加。完成度可超过 200%，但单项任务的 XP/金币奖励倍率最高按 200% 计算。门槛、奖励与候选模板集中在 `daily-reward-rules.js`，可按需调整。每日奖励领取记录按日期保存，同一天最多领取一次；领取不会扣金币、改变 XP 或产生商店兑换记录。

新建任务时计划日期默认为用户本地的今天；编辑已有任务会保留原日期，未排期任务仍可手动清空日期。

成就页默认提供 28 项成就，覆盖成长启程、科研、学业、求职、编程与自学、生活与习惯、Boss 挑战、奖励与探索 8 个分类。支持添加自定义成就，可选择系统支持的完成任务、分支任务、指定标签任务、Boss/子任务、完成日期、奖励兑换或每日奖励领取条件，并设置分类、像素图标和目标数量。自定义定义与解锁记录保存在当前应用数据中。默认成就和临时门槛集中在 `achievement-rules.js`；若已有记录满足条件，会在首次识别时补记解锁。成就只解锁一次，不额外发 XP 或金币；当前仅支持添加，暂不支持编辑或删除成就。

界面使用内置 SVG 像素符号，不依赖外部图标服务。顶部“音效”开关默认关闭；开启后，新建/编辑窗口、创建/保存任务、状态调整、完成任务、添加进展、删除任务、心情标记、成就解锁、奖励保存/兑换、领取每日奖励和余额不足等操作会播放不同的短促 8-bit 提示音。声音由浏览器实时合成，不读取外部音频；音效设置保存在应用数据中。

首次完成任务时由用户填写非负整数完成度，XP 和金币奖励分别按“任务设置奖励 × min(完成度, 200%) ÷ 100”加权，结果四舍五入为整数。0% 不发奖，100% 发放设置值，200% 及以上最多发放两倍。原始完成度和实际发放数值一并写入任务及奖励流水；重新打开任务不退还奖励，再次完成不重复发奖。

## 可调整的奖励默认值

奖励建议公式：类别基准 × 稀有度倍率 × Boss 倍率 × 重复周期倍率，结果四舍五入为整数；首次完成时再乘完成度 ÷ 100。支线基准为 16 XP / 6 金币，主线基准为 36 XP / 14 金币。稀有度倍率为普通 1.0、稀有 1.1、史诗 1.25、传说 1.5；Boss 倍率为 2.0；一次性、日常、周常倍率为 1.0、0.55、0.75。类别基准与周期倍率仍是可调整的建议值。修改 `reward-rules.js` 可调整规则。

累计 XP 阈值依次为 0、100、250、450、700、1000、1350、1750、2200、2700，此后每级增加 650 XP。等级高于 999 时界面显示“999+”，点击可查看实际等级。

Phase 2 旧任务保留；奖励系统启用前已完成的任务不追溯发奖，也不会伪造完成度评分。旧任务缺少奖励设置时按 0 处理。此前保存为“月常”的周期迁移为“一次性”。重复周期目前用于建议计算，自动生成新周期任务实例仍待后续实现。
